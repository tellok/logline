# Beta 发布流程

[English](./release-flow.md) | 简体中文

默认分支由 GitHub 元数据确定，当前为 master。此前默认分支的快照保留为 v1。单一发布包为 logline，Changesets CLI 固定为 2.29.7。首次发布为 2.0.0-beta.0，后续更新继续使用 beta 模式，正式 v2 发布另行决定。

## 事件与版本决策

1. 功能 PR 添加英文 Changeset 与 translations.json 中对应中文摘要，原生 PR 检查验收最新来源与目标的合并结果。
2. 默认分支 push 在安装依赖前检测未消费变更集，排除 README、隐藏文件、元数据与已消费的预发布 ID。候选格式错误由固定 CLI 明确阻断。
3. 有变更时，轻量工作流生成版本、双语 CHANGELOG、预发布消费记录与公开来源证明，创建或更新 codex/version-packages；不构建或上传产品。
4. 版本 PR 展示拟发布版本、基础源码 SHA、包、渠道与用户变更，不自动合并。首次发布按用户明确授权合并，后续由维护者决定。
5. 仅合法版本 PR 的实际合并提交允许交付，普通提交、功能 PR、手工标签或任意手工运行均不能发布。

版本 PR 必须使用 merge commit。当前契约拒绝 squash/rebase 合并。实际父提交必须与计划基础提交及版本 PR 来源一致；发布门禁核验仓库、实际默认分支、受管理分支、标记与标签、仅版本文件范围、版本、beta 渠道及变更集摘要，并在隔离检出中重放版本准备，逐字节比较所有版本文件后才允许产品构建。

预发布变更集保留在目录中，消费 ID 由 pre.json 记录。检测排除已消费 ID，因此不会因历史记录重复创建空版本 PR。

## 最新合并结果与信任边界

来源更新使用原生 pull_request 事件。目标分支 push 分页查找所有受影响开放 PR，包含非默认目标。仓库内协作者与授权自动化使用指向最新原生合并提交的不可变临时引用，确保检查配置、脚本、安装、测试和构建来自同一合并树；不修改来源或目标引用。检查前后核验来源、目标与父提交，陈旧结果明确失败，按 PR 隔离并发并取消旧检查。

外部 fork 保持 GitHub 原生执行审批。目标重检控制器不在特权上下文执行 fork 代码，而是登记 action-required 检查，等待维护者批准并执行最新原生合并结果验证。不宣称外部 fork 的目标更新已实现无需审批的自动验收，也不通过特权 dispatch 绕过审批。合并冲突或原生合并引用陈旧时失败，不能退回仅来源检查。

临时检查引用只在全部消费者完成后精确删除，包含失败与取消。可信完成监听核验仓库、引用模式、SHA、现存引用及活跃消费者，不执行上游代码。清理失败单独可见，可重试原清理运行或只删除确认后的陈旧引用。本流程没有临时 CI 文件制品。

## 质量门禁与一次构建

统一验证执行类型检查、ESLint、发布契约测试、产品测试、格式检查、一次构建与公开导出检查。本地结构化 Vitest 报告必须包含非空测试、全部通过及零跳过。报告不上传，日志与 Job Summary 记录计数。

独立的 CI matrix 使用打包后的产物，测试每个受支持 Vite 大版本（5、6、7、8）的最新稳定版本。每个消费者独立安装 Vite，检查严格公开类型、开发转换与依赖预构建、生产日志过滤、来源标注、base 注入、IndexedDB 自动初始化、HTML 启动捕获和 sourcemap。本地运行 `pnpm run build && pnpm run test:vite`，或追加 `-- 5` 选择单个大版本。仓库工具链保持 Vite 6，使 Vitest 与消费者的 Vite 版本独立运行。

PR 验证产物仅留在作业本地，不用于正式交付。通过来源门禁后，发布作业检出精确合并提交，重新验证、构建一次，然后关闭打包脚本，封装已验收 dist。同一压缩包以 beta 标签发布 npm，同时作为持久 GitHub 预发布资产上传，并附摘要和来源清单；不重新构建或上传 CI 中转副本。

Release 正文从双语 CHANGELOG 的本次精确版本章节生成。缺失或重复章节阻断，不混入旧版本或未发布变更。远端同名 npm 版本、标签及资产必须具有相同来源与摘要，否则失败，禁止覆盖。

## 权限与存储

检查作业只读仓库和 PR；版本准备具备内容、PR 与调度写权限；可信目标重检控制器仅维护检查和临时引用；发布来源门禁只读；合格交付具备内容写权限及 OIDC；完成监听只精确清理已终结检查引用。

npm 信任关系为 tellok/logline 的 release.yml，不限制 environment，允许直接 npm publish。使用 Node.js 24 与 npm 11.15.0，不保存长期 npm 发布令牌。产品、测试报告与打包文件只在作业本地消费；npm 包与 GitHub 正式资产独立持久保存。本流程不发布 Docker 镜像、不部署文档站，也没有临时传递制品。

## Beta 与最新 v1

发布显式指定 beta 标签，发布前后验证 latest 等于所有已发布稳定 v1 中最大的次版本和补丁版本，而不是固定的 1.0.0。本流程不会写入 latest。logline@beta 安装 v2，logline@1 限制在 v1 主版本，普通 logline 安装仍获得最新稳定 v1。

## 并发与恢复

版本准备串行并取消旧运行，准备前后核验默认分支是否前进，以精确租约更新受管理分支。PR 管理区域重写但保留外部人工说明，未知写入结果通过回读确认。

发布串行但不取消。手工恢复必须指定合法版本 PR 的精确合并 SHA，并重做来源与质量检查。npm 已发布而 GitHub 资产失败时，重跑原来源核验 npm 摘要后只补齐缺失的匹配资产。执行器丢失后从原始合格源码重建本地文件。GitHub 预发布不设置为 latest。

## 验收证据

本地契约测试覆盖 beta 限制、最新 v1 选择、精确章节及变更集检测。真实上线将验证功能 PR、自动版本 PR、最新合并结果、来源重放、OIDC 发布与默认安装保护，并记录实际结果。不将尚未执行的 fork 审批及取消故障场景表述为已通过。

依据：[版本 PR 发布 Skill](https://github.com/tellok/dotai/tree/main/skills/design-pr-versionization)、[Changesets 预发布](https://changesets.dev/guide/prereleases)、[npm 可信发布](https://docs.npmjs.com/trusted-publishers/)。

## 在线文档

双语 VitePress 站点部署在 https://tellok.github.io/logline/（英文）和 https://tellok.github.io/logline/zh/（简体中文），Pages 来源设置为 GitHub Actions。PR 检查构建两种语言并拒绝失效的内部链接。

经核验的 npm 与 GitHub Release 交付成功后，文档作业检出相同的发布 SHA，构建一次并通过 github-pages 环境部署。普通提交和版本准备不部署文档。站点的 release.json 记录实际包版本与源码 SHA。重跑原发布会使用原始源码恢复文档，不使用最新分支代替。

Pages 部署需要一个供 deploy-pages 消费的临时制品。部署尝试结束后，作业删除该精确制品；执行器丢失导致无法清理时，一天过期限制保留时间。删除临时制品不会移除已部署的站点。文档构建或部署失败使发布流水线失败；已成功上传的 npm 版本仍保留，恢复时核验其内容。

本地使用 pnpm docs:dev、pnpm docs:build 和 pnpm docs:preview。README 和 Markdown 指南是唯一内容来源；生成的暂存目录和站点产物均被忽略且不进入 npm 包。
